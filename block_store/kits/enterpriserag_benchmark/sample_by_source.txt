Fix variant skew when stickiness key is missing (use high-entropy fallback + Console warnings)

Context
We’ve seen skewed allocations in beta (most notably eu-west) when callers do not provide a stickiness key. The root cause was our “safe default” for bucketing: when the stickiness key source resolution produced an empty value, we were hashing a low-entropy sentinel (effectively a constant) which deterministically mapped the entire missing-key population to the same bucket → variant.

This PR fixes the data plane bucketing behavior to keep traffic splits correct even when stickiness is missing, and adds guardrails in Console so customers understand the tradeoff (even distribution but non-sticky assignment).

What changed
1) Policy engine / router bucketing
- Previous behavior:
  - stickiness_key = resolveStickyKey(req)  // may be "" / null
  - key_for_hash = stickiness_key ?? "unknown"
  - bucket = hash(experiment_id + route_id + key_for_hash)
  - Result: all missing-key requests share key_for_hash="unknown" → same bucket.
- New behavior:
  - If resolveStickyKey(req) yields a non-empty key: keep existing deterministic + sticky assignment.
  - If missing:
    - Use a high-entropy per-request fallback for bucketing only (req.request_id), explicitly marked as non-sticky.
    - Emit an internal annotation so we can debug / measure: assignment_key_source="request_id" and assignment_is_sticky=false.
    - Add a counter metric: route_experiments_missing_sticky_key_total{route_id, experiment_id}.

Rationale: Without a stable identifier we cannot be both sticky and well-distributed. For beta/GA safety we prioritize correct split distribution (avoids “variant 0 traffic” incidents) while making the non-sticky nature explicit in telemetry and UX.

We need a secure, auditable mechanism that allows long-running analytics ETL workers running in our AWS analytics-prod account to read objects from a GCS bucket in the GCP analytics-prod project and write them to an S3 bucket in the AWS account. - Current workaround uses service-account JSON in a secrets store which increases blast radius and requires manual rotations.
- ETL pipelines for nightly reports and feature-store materialization are blocked from migrating to the new partitioned job runner until a secure cross-cloud identity pattern is in place.
- Compliance wants CloudTrail / Cloud Audit logs tied to a single auditable gateway identity.

3) Gateway enforces per-job least-privilege scoping (object prefix and read-only) via IAM conditions and expires tokens within 15m.
